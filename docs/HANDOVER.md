## Ground rules that are not negotiable

These are in `ROADMAP.md` in full. The short version:

1. **Licences: permissive only.** MIT, ISC, BSD, Apache-2.0, 0BSD, Unlicense, CC0. No GPL, LGPL,
   AGPL, MPL, or anything share-alike. `npm run license:check` enforces this and runs in CI.
   **Check a dependency's licence and its transitive dependencies before installing it** — an
   install that fails the gate is painful to unpick. This is why the project is on Vite 7 and
   Vitest 4 rather than 8 and 5: those pull in MPL-2.0 `lightningcss`. It is also why Excel
   reading/writing is a small in-repo module over `fflate` instead of `exceljs`, and why PDFs are
   produced by the browser's print dialog instead of `pdf-lib` (which needs Zlib-licensed `pako`).
2. **IDs are UUIDv7** everywhere, generated by `newId()` in shared. No auto-increment.
3. **Never convert between currencies.** A pledge is promised in one currency; money paid in
   another is reported beside it and never netted off. One helper does this everywhere:
   `pledgePayments()` in `packages/shared/src/money.ts`. Do not do this arithmetic by hand.
4. **No new dependencies** without a reason and a licence check.

## Security posture — understand this before touching the API

- Every `/api/*` route is matched against the `RULES` table at the top of `app.ts`, which maps a
  route prefix to a required permission. **It denies by default**: a path matching no rule is
  refused. Paths are matched **lower-cased**, and Express is set to route case-sensitively
  *before the first `app.use`* (it builds its router on that first call, so the order matters).
  Both guards exist because `POST /api/RESET` once slipped past a lower-case-only table.
- Roles and permissions live in `packages/shared/src/auth.ts` and are shared with the web app,
  which uses them only to hide things. **The API is what enforces them.**
- **The member portal never takes a family id from the browser.** `portal.scope()` resolves the
  family from the signed-in user's own member record and everything starts from there. Reaching
  another family answers **404, not 403**, so an id is never confirmed to exist. Keep it that way.
- Sessions are a random token in an httpOnly SameSite=Lax cookie; only the token's SHA-256 is
  stored. Passwords are scrypt with a per-user salt and the cost recorded in the hash.
- **Nothing that is a credential may reach the logs.** The request logger in `app.ts` redacts ids,
  backup names and invite/reset tokens. If you add a route with a secret in its path, redact it.

## Conventions

- Comments explain **why**, never what the line obviously does. Few and meaningful.
- UI text is plain, warm English in sentence case. No jargon, no "Oops", no exclamation marks.
  Use the shul's own words via `useSettings().t()` for family/member/pledge/donation — a shul may
  call them households or congregants. Format money with `useSettings().money()`.
- Everything configurable is already configurable: date types, funds, payment methods, currencies,
  member roles and note types are editable lists; terminology and feature switches are settings.
  **Do not hard-code a list that belongs in Settings.**
- Schema changes are **numbered migrations** in `apps/api/src/migrations.ts` with a `schema_version`
  table. **Never edit a migration that has shipped** — add a new one.
- Line endings are LF, enforced by `.gitattributes`.

## Gotchas that will cost you time

- **Writing code through the shell mangles it.** Backticks, `\u` escapes and apostrophes inside
  `node -e "..."` or heredocs get eaten by bash, and have silently corrupted regexes and template
  literals in this repo before. Write a `.cjs` script to the scratchpad with a file-writing tool
  and run that, or use the dedicated edit tools.
- **The dev API watches only `apps/api/src` and `packages/shared/src`.** That is deliberate: it used
  to restart whenever anything touched `node_modules`, which interrupted test runs.
- The Vite dev proxy uses `changeOrigin: false` so the API sees the browser's host and the
  invitation links it builds point at the app rather than the API's port.
- If you delegate to subagents, **do not let them run repo-wide `tsc`/`lint` concurrently** —
  they fight over TypeScript's build-info files. Give each agent disjoint files and run
  `npm run check` yourself at the end.
- `apps/api/data/` is gitignored and holds real local data plus backups. Do not commit it, and take
  a backup (Settings → Data, or `POST /api/backups`) before anything destructive.
